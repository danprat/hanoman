- [audit SPEC-383 — setting model sesi: blok claude/codex tak terbedakan & konflik tak punya default sendiri](research/audit-spec-383-setting-model-sesi.md) — dua temuan. **A (UI):** di tab Settings "Model sesi", blok codex diberi nama eksplisit (`Model codex`/`Effort codex`) sementara blok claude hanya berbunyi `Model`/`Effort` — nama agennya cuma hidup di `aria-label`, tak terlihat mata (dibuktikan dump DOM); lebih buruk, judul kartunya "Model sesi — **default global**" tetap terpampang di atas blok claude meski `Setting.agent = "codex"`, padahal `sessionAgentDefaults()` saat itu membaca `codex.model` — layar menampilkan "default global = Opus 5" sementara sesi berikutnya lahir `gpt-5.6-terra`. Plus katalog claude terduplikasi (`S_MODELS`/`S_EFFORT` menyalin `MODELS`/`EFFORTS` shared, komentarnya sendiri berbunyi "keep in sync"). **B (fitur absen):** ketiga pintu konflik memakai `sessionAgentDefaults()`, tak ada override per-request (sadar, SPEC-377) **dan** tak ada knob Settings — jadi tak ada satu tempat pun untuk menyetel model sesi konflik tanpa memindahkan model semua sesi kerja, padahal `IntegrateDialog` sudah menjanjikan "memakai agen, model & effort dari Settings". Fix (Spec/Plan skipped, **ADR-0081**, tanpa migration/endpoint): blok `Setting.conflict` opt-in + `conflictSessionDefaults()` di 3 route + tab Model sesi ditata ulang bersumbu agen (dua blok berjudul + badge aktif) + katalog claude dibaca dari shared

"claude"`. Terukur dari argv pane tmux dengan `Setting = {agent:"codex", codex:{model:"gpt-5.6-terra", effort:"high"}}`: ketiga jalur melahirkan `--model claude-opus-5 --effort xhigh --dangerously-skip-permissions` (= `DEFAULT_SETTING`, bukan nilai tersimpan). **Kontrol negatif** membuktikan ini murni percabangan agen yang hilang: dengan `agent:"claude"` + `model:"claude-sonnet-5"`, argv-nya sudah benar — karena itu bug ini tak terlihat sampai agen default dipindah ke codex. Fix (Spec/Plan skipped, tanpa ADR/skema/kontrak): `sessionAgentDefaults()` + `agent` + `ensureCodexTrust` di kedua berkas (`finishGraphOp` menerima `repoDir` dari pemanggil, menutup keempat op sekaligus)
