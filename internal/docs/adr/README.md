# ADR — index & riwayat keputusan

Sub-index dari [internal/docs/README.md](../README.md). Index utama menyimpan daftar **satu baris per
ADR**; berkas ini menyimpan **narasinya** — apa yang diperluas, dicabut, atau diamandemen tiap
keputusan, berikut gotcha yang harus diingat. Pemisahan ini dilakukan di SPEC-386: index utama dibaca
setiap sesi agen, riwayat ADR hanya saat seseorang butuh alasannya.
> Nomor unik & imutable. ADR usang tidak dihapus — ditandai statusnya di bawah dan di header masing-masing.
- [0084 — Sesi backlog dilanjutkan, bukan diulang dari nol](0084-melanjutkan-sesi-backlog.md) — **memulihkan substansi 0017** (yang ikut tercabut bersama 0024) di arsitektur sesi interaktif, melengkapi 0015/0002/0030/0019, **TIDAK menyentuh** 0037/0074 (SPEC-394): `startSpecSession` punya **tiga** keadaan, bukan dua — **live** (pane tmux hidup → re-attach), **resume** (`stage ≠ done` + `baseSha` ada + artefak masih ada → lanjutkan, `201 { id, resumed: true }`), **fresh** (perilaku lama). **Pane MATI bukan sesi**: `remain-on-exit on` menahannya hanya agar layar terakhirnya terbaca, dan mengembalikannya sebagai sesi membuat tombol "Lanjutkan" **diam** — UI sudah menghitung `!exited`, jadi tombol itu muncul persis saat pane mati, lalu satu-satunya jalan keluar (Tutup) justru **menghapus worktree-nya**. Dua bentuk resume: worktree `.worktrees/<id>` yang masih sah dipakai **apa adanya** (satu-satunya jalur yang TIDAK memanggil `addWorktree` — helper itu selalu merebut path dengan `remove --force` + `rmSync`, benar sebagai *reclaim*, fatal sebagai "lanjutkan"), atau — bila worktree hilang — dibangun ulang `--detach` di tip **`origin/hanoman/<id>` → `hanoman/<id>` → `Spec.headSha`**. Urutan itu mengikat: `origin/…` adalah ref yang `git push` di akhir sesi harus fast-forward, dan worktree yang lahir dari `branchFrom` membuat push itu **ditolak non-fast-forward** (diuji langsung ke git — sesi ulangan bahkan tak bisa menyimpan hasil ulangannya). `baseSha`/`headSha` **tak pernah ditulis ulang saat resume**; prompt `resumePrompt` menyebut baris fase yang **sudah tercatat** (berkas fase hidup di luar worktree → selamat dari penghapusan, dan agen tak bisa menurunkannya sendiri) dan **tak mengulang** klausa keputusan pasca-Audit begitu `Audit` tercatat. Server **tak pernah menulis** `$HANOMAN_PHASE_FILE`. `stage = done` tetap jalur SPEC-172. Premis 0024 yang membatalkan 0017 ("sesi tmux tak pernah terputus") **terlalu kuat**: benar untuk restart API, salah untuk mesin restart / agen keluar / operator menutup sesi. Gerbang pane-mati dipasang di **titik cekik `createSession`**, jadi ia menutup sekaligus jalur tanpa gerbang sendiri (sesi konflik `merge-<spec>` & `finishGraphOp`, konsol VPS `vpsc-<id>`); kelima route **project-level** (reverse·scaffold·prd·breakdown·cross-audit) ikut disempitkan ke `!exited` — **berpasangan wajib** dengan `ensureWorktree()` yang melewati `addWorktree` bila worktree masih sah, karena memperbaiki gerbangnya sendirian menukar "tombol diam" dengan **kehilangan dokumen belum-commit**; prompt flow itu cukup diberi satu kalimat `RESUMED_WORKTREE_NOTE` (bukan `resumePrompt` — deliverable-nya dokumen, fasenya tak punya artefak berkotak). `attach()` pada pane mati tetap sah. Tanpa skema/migration/endpoint baru
